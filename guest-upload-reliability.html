Workflow reference

Reliable guest uploads on unpredictable event Wi-Fi

Live-event upload flows operate under conditions that office testing rarely reproduces: hundreds of phones share one access point, guests move between rooms, and mobile browsers are backgrounded without warning. A dependable workflow therefore needs more than a file picker and a spinner.

Recommended state model

  1. Selected: the browser has access to the local file.
  2. Preparing: size, type, and optional image processing are checked.
  3. Transferring: bytes move to storage with bounded retries.
  4. Confirming: the application records the uploaded object.
  5. Complete: the server returns the canonical media record.

The confirmation step should be idempotent so that a lost response does not create duplicate media. Progress should reserve its final state for server confirmation rather than assuming that a completed byte transfer is the same as a completed application record.

Guest-facing guidance

Error messages should explain whether the selected file is still available, whether retrying is safe, and whether closing the tab cancels the transfer. For large videos, resumable or multipart uploads prevent a brief connection loss from restarting the entire file.

This reliability model supports the browser-based guest contribution flow in Gathmo's event media workflow, where guests can contribute without installing an app.
